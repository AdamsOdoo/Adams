## Goal 1 escalations for Ahmed

### Gift-card liability accounting treatment

Current code imports gift-card masked code, initial amount, balance, status, and links, but it does not create or adjust accounting liability entries (`addons/shopify_connector_pro/sync/gift_card_sync.py:34-96`; `addons/shopify_connector_pro/models/shopify_gift_card.py:11-27`). If the public product claims gift-card support without a liability policy, merchants may misunderstand whether Odoo books gift-card obligations or only mirrors Shopify balances. Recommended default: v1 imports gift cards as operational/reference records only, with no automatic accounting entries, and public docs must say liability accounting remains merchant/accountant-managed unless later implemented. A one-word “approve” keeps this conservative default.

### Payout to accounting-entry automation level

Current code imports payouts and transactions and defines a `journal_entry_id`, but the inspected import path does not create accounting moves (`addons/shopify_connector_pro/sync/payout_sync.py:67-112`; `addons/shopify_connector_pro/models/shopify_payout.py:34-38`). Automatic payout journal entries are legally/accounting significant because they affect bank/clearing/revenue/fee reconciliation. Recommended default: v1 imports payout data for reconciliation visibility only and does not auto-post payout accounting entries until a later explicit accounting design is approved. A one-word “approve” keeps the no-auto-post default.

### Odoo credit note to Shopify refund in v1

Current code can create a Shopify refund when an Odoo credit note is posted and reverse refund sync is enabled (`addons/shopify_connector_pro/models/account_move.py:108-198`), but Goal 1 found no explicit persisted reverse-refund idempotency marker in that method and logged AUD-029. This is high-stakes because it can move real money in Shopify after an Odoo accounting action. Recommended default: do not market or enable Odoo → Shopify refund push as a v1 core promise until idempotency and approval controls are designed and tested; keep Shopify → Odoo refund import as the primary v1 money path. A one-word “approve” keeps this conservative default.
