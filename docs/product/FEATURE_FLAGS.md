# Feature Flags

Goal 2 Phase B implementation complete in this branch; Odoo.sh confirmation remains pending until relayed.

## Purpose

Track features that may be staged, hidden, or enabled by scope while protecting core reliability, financial correctness, and merchant UX.

## Core vs Advanced Feature Rule

Core merchant flows required for a correct Shopify Connector Pro Ultimate Edition v1 should not be hidden merely to avoid defining them. Advanced or optional capabilities may be staged behind feature flags when doing so preserves reliability, financial correctness, and release safety.

## NOT FLAGGABLE — CORE

- Orders: core merchant revenue workflow; order cron and webhooks are required (`addons/shopify_connector_pro/data/shopify_cron.xml:22-29`, `addons/shopify_connector_pro/models/shopify_webhook_log.py:183-185`).
- Products: core catalog workflow; can have direction settings, but product infrastructure should not be removable (`addons/shopify_connector_pro/data/shopify_cron.xml:4-11`, `addons/shopify_connector_pro/models/shopify_webhook_log.py:179-182`).
- Customers: core order/customer identity workflow (`addons/shopify_connector_pro/data/shopify_cron.xml:13-20`, `addons/shopify_connector_pro/models/shopify_webhook_log.py:186-187`).
- Inventory: core availability workflow (`addons/shopify_connector_pro/data/shopify_cron.xml:31-38`, `addons/shopify_connector_pro/models/shopify_webhook_log.py:188`).
- Shopify refund import: core money-correction workflow; Shopify → Odoo refund import remains the primary v1 refund path (DEC-027) and current cron exists (`addons/shopify_connector_pro/data/shopify_cron.xml:67-74`).
- Webhook infrastructure and logs: required for visible/retryable event handling (`addons/shopify_connector_pro/data/shopify_cron.xml:40-47`, `addons/shopify_connector_pro/controllers/webhook.py:178-188`, `addons/shopify_connector_pro/models/shopify_webhook_log.py:108-126`).
- Sync logs, import jobs, and error digest: required for no-silent-failure UX (`addons/shopify_connector_pro/data/shopify_cron.xml:85-92`, `addons/shopify_connector_pro/data/shopify_cron.xml:112-119`, `addons/shopify_connector_pro/views/shopify_menu.xml:221-242`).
- Reconciliation: required money/operational visibility (`addons/shopify_connector_pro/data/shopify_cron.xml:94-101`).
- Total-check guard: permanent never-wrong-money product behavior after DEC-011/012/024 closure.
- Setup/onboarding and backend configuration: core install/setup flow, though Goal 4 will lock/validate settings.

## Flag Semantics

- OFF hides menus/views and disables scheduled processing where applicable.
- Scheduled jobs for disabled features are quietly skipped by domain/out-of-scope behavior; intentionally disabled crons should not create recurring sync-log or chatter noise.
- Visible disabled-feature messaging applies to user-triggered actions and inbound webhooks.
- Inbound webhook events for disabled features must never be silently dropped; they must be logged/skipped visibly, not ignored.
- Existing records remain; turning a feature OFF never deletes records, bindings, logs, or audit evidence.
- Only admin-level users can flip feature flags.
- Settings lock/validation belongs to Goal 4; Phase A records this dependency but does not design it.
- Money-path flags must keep existing safety guards, activities, and audit evidence; turning a feature ON cannot bypass total-check, tax/currency validation, idempotency, or no-silent-failure rules.
