# Installing the Executive Dashboard addons

**Scope:** Odoo 19 Enterprise on Odoo.sh or a comparable supported on-premise installation. Odoo Online, Community-only installations, earlier Odoo versions and missing Enterprise `account_reports` are outside the tested dependency contract. This guide is a reproducible configuration procedure, not a fresh-install qualification certificate.

## Package and prerequisites

The release package contains the unchanged addon paths `addons/adams_executive_dashboard/` and `addons/adams_dashboard_finance/`. Their manifests in this candidate declare version `19.0.1.6.0`. The core depends on `web` and `account`; the finance addon depends on the core and Enterprise `account_reports`. Optional Sales, Inventory, Purchase, CRM, Employees, Attendances, Time Off and Planning applications are *not* manifest dependencies and should not be installed merely for a demo. Their screens show installed/authorized, empty, restricted or missing-app states according to the current database.

1. Back up a development database and verify that its Odoo version is 19 Enterprise and its own `account_reports` is installed and licensed. Put both directories in the custom addons path of a **development branch**. Do not copy customer data, company IDs or mapped report IDs from Adams staging.
2. Update the Apps list and install **Adams Dashboard — Native Financial Reports**, which installs the core by dependency. If the finance addon is unavailable, confirm its Enterprise dependency and Apps filter before continuing. Review the user groups in Dashboard Settings and the user's existing accounting/source module rights; dashboard membership does not grant accounting, HR or inventory rights.
3. Open Executive Dashboard. The company name/logo come from the currently active standard Odoo Company record, including changes on refresh. Select a valid period. Operational sections use installed applications and source access. Financial cards without an approved mapping deliberately read as configuration required; zero or fictional values must never substitute.
4. An **accounting manager** opens Dashboard financial mappings, chooses the company's installed native report variant, exact line expression and unit/date basis per metric, checks its source results in Odoo's report at matching company/period/currency, records a clear definition note and approves the mapping. Configure the cash General Ledger detail and Cash Flow Statement only when available and independently reconciled. Approvals are company specific and invalidated if the approved report definition changes. Repeat this for each company/localization; no staging numeric IDs are portable.
5. Reopen and refresh the dashboard. Test a representative signed P&L, Balance Sheet, cash and aging value against standard Odoo reports at the same filters. Open source actions, verify logo/name refresh, optional-app states, permissions, exports and Arabic/light/dark if used.

**Upgrade:** back up the database, deploy both newer addon directories together on a development branch, upgrade the finance addon and core through the standard Apps upgrade flow, then check installed versions, assets, approvals and representative native totals. The report mapping's fingerprint deliberately requires reapproval after source-definition drift. On Adams staging, Odoo.sh ran the exact two-module `-u` upgrade from installed `19.0.1.5.0` to `19.0.1.6.0` after a manual backup; this is a populated staging upgrade, not a separate clean-database portability test. **Uninstall:** first remove the finance addon, then the core through Apps on a disposable database and confirm no residual dashboard menus/ACLs/assets. Uninstall and upgrade on a separate clean database remain unverified for this candidate.

## Qualification still required

A fresh install and upgrade from `19.0.1.5.0` on a separate disposable Odoo 19 Enterprise database; two distinct companies/localizations; clean uninstall; native report mapping approval and reconciliation; version/asset/translation and source-access checks. Until those checks pass, describe the ZIP as an **installable source package**, not a proven plug-and-play deployment.
