## 1. Odoo 19 — `sale_stock` is auto-installed (Task 012 correction basis)

- **[Fact]** `addons/sale_stock/__manifest__.py` on `odoo/odoo` branch
  19.0 contains exactly: `'depends': ['sale', 'stock_account'],` and
  `'auto_install': True,` (direct quotes). Name: "Sales and Warehouse
  Management"; description: "This module makes the link between the
  sales and warehouses management applications." Note: the dependency
  is `stock_account` (which pulls `stock` transitively), not `stock`
  directly.
  (https://raw.githubusercontent.com/odoo/odoo/19.0/addons/sale_stock/__manifest__.py
  — Accessible 2026-07-11)
- **[Fact]** `auto_install` semantics (manifest reference, 19.0): "If
  `True`, this module will automatically be installed if all of its
  dependencies are installed. It is generally used for 'link modules'
  implementing synergetic integration between two otherwise
  independent modules." (direct quote)
  (https://www.odoo.com/documentation/19.0/developer/reference/backend/module.html;
  source raw.githubusercontent.com/odoo/documentation/19.0/content/developer/reference/backend/module.rst
  — Accessible 2026-07-11)
- **[Fact]** On sale-order confirmation with `sale_stock` installed,
  pickings are generated via stock rules: `sale_stock/models/sale_order.py`
  overrides `_action_confirm` with `self.order_line._action_launch_stock_rule()`
  (direct quote); `_action_launch_stock_rule` "Launch procurement run
  method with required/custom fields generated by a sale order line"
  (direct quote from the 19.0 source docstring).
  (https://raw.githubusercontent.com/odoo/odoo/19.0/addons/sale_stock/models/sale_order.py;
  …/sale_order_line.py — Accessible 2026-07-11)
- **Consequence [Inference]:** whether a confirmed imported order
  creates a delivery picking depends on the **installed Odoo apps**
  (`sale_stock` present whenever `sale` + `stock_account` are both
  installed, because it is auto-installed), NOT on the connector
  edition. Any design statement of the form "Lite means no pickings"
  is unsupported and is corrected in the Task 012 packet and the
  packaging proposal this session.

## 3. Odoo 19 — browser-level UI testing mechanisms (UI packet basis)

- **[Fact]** Tours are the official integration-test mechanism:
  "Tours (see Integration Testing): tours simulate a real situation.
  They ensures that the python and the javascript parts properly talk
  to each other." Started from Python via `odoo.tests.HttpCase` +
  `start_tour` ("To start a tour from a python test, make the class
  inherit from HttpCase, and call `start_tour`" — direct quote;
  example `self.start_tour("/web", "your_tour_name", login="admin")`);
  tours register as `web_tour.tour` records.
  (https://www.odoo.com/documentation/19.0/developer/reference/backend/testing.html
  — Accessible 2026-07-11)
- **[Fact]** HOOT is the 19.0 JS unit-test framework: "Odoo developers
  use a home-grown testing framework called HOOT (Hierarchically
  Organized Odoo Tests)" (direct quote); "In Odoo, frontend unit tests
  can be run by going to the `/web/tests` URL" (direct quote). The
  HOOT library exists at `addons/web/static/lib/hoot/` on 19.0.
  (https://www.odoo.com/documentation/19.0/developer/reference/frontend/unit_testing.html
  — Accessible 2026-07-11)
- **[Open question]** QUnit's removal status in 19.0 is
  documented-by-omission only; HOOT is the documented framework —
  plan tests on HOOT + tours, never QUnit.

## 6. Odoo 19 — price precision and currency rounding (tolerance basis)

- **[Fact]** `decimal.precision` record "Product Price" defaults to
  **2 digits** (`addons/product/data/product_data.xml`, direct quote of
  the record).
  (https://raw.githubusercontent.com/odoo/odoo/19.0/addons/product/data/product_data.xml
  — Accessible 2026-07-11)
- **[Fact]** `res.currency.rounding` default `0.01`, help "Amounts in
  this currency are rounded off to the nearest multiple of the
  rounding factor."; `decimal_places` is computed
  `int(math.ceil(math.log10(1/currency.rounding)))` — i.e.
  **currency-specific decimal places exist per `res.currency`
  record** (0 for a rounding of 1.0, 3 for 0.001). (direct quotes)
  (https://raw.githubusercontent.com/odoo/odoo/19.0/odoo/addons/base/models/res_currency.py
  — Accessible 2026-07-11)

## 7. Odoo hosting — encryption at rest (DEC-028 Rung-1 basis)

- **[Vendor statement — Odoo about its own cloud]** odoo.com/security:
  "All customer data (database content and stored files) is encrypted
  at rest, both in production and in backups with AES-256"; "All data
  communications with client instances are protected with 256-bit SSL
  encryption (HTTPS)."; backups "History of 14 full backups … 1/day
  for 7 days, 1/week for 4 weeks, 1/month for 3 months", "Backups
  replicated in at least 3 different data centers." (quotes as
  extracted 2026-07-11; per the raw-text caution above, re-confirm
  verbatim before quoting in any customer-facing document)
  (https://www.odoo.com/security — Accessible 2026-07-11)
- **Boundary [Fact, restated]:** this is a hosting/platform-layer
  property. Odoo 19 core has no field-level/ORM encryption mechanism
  (AR-022, unchanged). DEC-028 Rung 1 relies on **verified
  infrastructure encryption evidence per deployment**, never on an
  application-code claim.

## 8. Odoo 19 — ACLs govern access; view/field `readonly` is UI-only (SEC-1 basis)

- **[Fact]** Security docs (19.0): "Odoo provides two main data-driven
  mechanisms to manage or restrict access to data" (access rights +
  record rules, both group-linked); "On public methods, the record on
  which a method is executed and the parameters can not be trusted,
  ACL being only verified during CRUD operations." (direct quotes)
  (https://www.odoo.com/documentation/19.0/developer/reference/backend/security.html
  — Accessible 2026-07-11)
- **[Fact]** ORM field reference (19.0, `odoo/orm/fields.py`
  docstring): "`readonly`: whether the field is readonly (default:
  `False`) **This only has an impact on the UI. Any field assignation
  in code will work** (if the field is a stored field or an inversable
  one)." (direct quote) — i.e. view/field readonly is **not** a
  security mechanism; server-side guards are required. Cite this ORM
  reference, not the security page (the phrase does not appear there).
  (https://raw.githubusercontent.com/odoo/odoo/19.0/odoo/orm/fields.py
  — Accessible 2026-07-11)

## 9. Shopify — variant/option limits and variant pagination (Task 010B basis)

- **[Fact]** "By default, stores have a limit of 2048 product variants
  for each product." (direct quote, `productSet` reference, 2026-07).
  The 2,048 limit is GA for all merchants since 2025-10-15 ("create
  products with up to 2,048 variants", an increase from "our
  historical variant limit of 100" — direct quotes, changelog);
  merchants using apps that do not use in-support GraphQL product
  APIs "may have a downgraded or broken experience … with more than
  100 variants" (direct quote fragment).
  (https://shopify.dev/docs/api/admin-graphql/latest/mutations/productSet;
  https://shopify.dev/changelog/the-product-variant-limit-is-now-2048-for-all-merchants
  — Accessible 2026-07-11)
- **[Fact]** Options: "Each product can have up to three options."
  (direct quote, Help Center); the Admin API expresses the limit via
  `Shop.resourceLimits.maxProductOptions` (Product reference).
  (https://help.shopify.com/en/manual/products/variants/add-variants;
  https://shopify.dev/docs/api/admin-graphql/latest/objects/Product
  — Accessible 2026-07-11)
- **[Fact]** Pagination: connections return "up to a maximum of 250
  resources" per page (direct quote, pagination guide) via
  `first`/`after` + `pageInfo { hasNextPage endCursor }`; exception —
  "If querying a single product at the root, you can fetch up to 2048
  variants" on `Product.variants` (direct quote, Product reference).
  **[Open question]** No documented default page size — always pass
  `first` explicitly.
  (https://shopify.dev/docs/api/usage/pagination-graphql;
  …/objects/Product — Accessible 2026-07-11)
- **[Fact]** `productCreate` "only supports creating a product with
  its initial product variant. To create multiple product variants
  for a single product and manage prices, use the
  productVariantsBulkCreate mutation." (direct quote);
  `productVariantsBulkCreate` accepts up to 2,048 variants per
  operation (migration guide). REST product/variant endpoints are
  deprecated; "The REST Admin API is a legacy API as of October 1,
  2024." (direct quote).
  (…/mutations/productCreate; …/mutations/productVariantsBulkCreate;
  https://shopify.dev/docs/apps/build/graphql/migrate/new-product-model;
  https://shopify.dev/docs/api/admin-rest;
  https://shopify.dev/changelog/deprecation-timelines-related-to-new-graphql-product-apis
  — Accessible 2026-07-11)
- **[Fact]** `ProductVariant.compareAtPrice` exists: "The
  compare-at price of the variant in the default shop currency."
  (direct quote; type `Money`). `ProductVariant.media` is the current
  media connection; the older `image` field is Deprecated.
  (…/objects/ProductVariant — Accessible 2026-07-11)
- **[Fact]** Product deletion/archival detection: `PRODUCTS_DELETE`
  webhook topic ("Occurs whenever a product is deleted"); no dedicated
  archive topic — archival surfaces via `PRODUCTS_UPDATE` and
  `Product.status` (`ACTIVE`/`ARCHIVED`/`DRAFT`; ARCHIVED = "The
  product is no longer being sold and isn't available to customers on
  sales channels and apps." — direct quote). Pull-based scans read
  `status` + a null product node for deletion.
  (…/enums/WebhookSubscriptionTopic; …/enums/ProductStatus — Accessible 2026-07-11)

## 10. Shopify — current media/file APIs, async processing (Task 015B basis)

- **[Fact]** `fileCreate`: "Creates file assets for a store from
  external URLs or files that were previously uploaded using the
  `stagedUploadsCreate` mutation." and "Files are processed
  asynchronously. Check the fileStatus field to monitor processing
  completion." (direct quotes); ≤250 files per batch;
  `FileCreateInput.originalSource` = "An external URL (for images
  only) or a staged upload URL." (direct quote);
  `duplicateResolutionMode` (default APPEND_UUID).
  (https://shopify.dev/docs/api/admin-graphql/latest/mutations/fileCreate;
  …/input-objects/FileCreateInput — Accessible 2026-07-11)
- **[Fact]** Deprecations: `productCreateMedia` — "Deprecated. Use
  productUpdate or productSet instead."; `productDeleteMedia` —
  "Deprecated. Use fileUpdate instead." (direct quotes). Current and
  non-deprecated: `fileCreate`, `fileUpdate`, `fileDelete` ("Deletes
  file assets that were previously uploaded to your store."),
  `productReorderMedia` (async — "The mutation returns a `Job` to
  track the reordering progress."), `productVariantAppendMedia`,
  `productVariantDetachMedia` ("Detaches media from product
  variants.", requires `write_products`).
  (per-mutation pages under …/mutations/ — Accessible 2026-07-11)
- **[Fact]** `Media.status: MediaStatus!` with enum UPLOADED ("Media
  has been uploaded but not yet processed."), PROCESSING, READY
  ("Media is ready to be displayed."), FAILED ("Media processing has
  failed.") (direct quotes).
  (…/interfaces/Media; …/enums/MediaStatus — Accessible 2026-07-11)
- **[Fact]** Official best practice: "Use `fileCreate` when your files
  are already accessible at a public URL. … you provide a URL and
  Shopify handles downloading, processing, and storing the file." and
  "Files are processed asynchronously. You poll the `fileStatus`
  field until it's `READY`, then associate the file with products
  using the file ID." (direct quotes). Reordering: "Use
  `productReorderMedia` to change media order without deleting and
  re-adding items." (direct quote). Binary uploads (files not at a
  public URL — the Odoo case) go through `stagedUploadsCreate` first.
  (https://shopify.dev/docs/apps/build/online-store/product-media;
  https://shopify.dev/docs/apps/build/graphql/migrate/new-files-model
  — Accessible 2026-07-11)

## 11. Shopify — money precision and non-two-decimal currencies (tolerance basis)

- **[Fact]** `Money` scalar: "A monetary value string without a
  currency symbol or code. Example value: `\"100.57\"`."; `Decimal`
  scalar: "A signed decimal number, which supports arbitrary
  precision and is serialized as a string." (examples `"29.99"`,
  `"29.999"`); `MoneyV2.amount: Decimal` "allowing for precise
  representation of cents or fractional currency". (direct quotes)
  (…/scalars/Money; …/scalars/Decimal; …/objects/MoneyV2 — Accessible 2026-07-11)
- **[Fact]** Zero-decimal display formatting default
  (`amount_no_decimals`) applies to: BIF, CLP, DJF, GNF, ISK, JPY,
  KMF, KRW, PYG, RWF, UGX, UYI, VND, VUV, XAF, XOF, XPF (direct
  quote, Help Center currency-formatting page — a display-formatting
  statement, not an API-precision statement).
  (https://help.shopify.com/en/manual/international/pricing/currency-formatting
  — Accessible 2026-07-11)
- **[Open question]** Shopify's storage/rounding policy for
  three-decimal currencies (BHD/KWD/OMR/TND — all present in the
  `CurrencyCode` enum) is not stated on any page fetched this
  session; the Task 012 tolerance design therefore keys on the ODOO
  currency's `rounding`/`decimal_places` (§6) and treats the Shopify
  amount string at face value, with a named dev-store empirical check
  for a three-decimal-currency order before any such store is
  onboarded.

## 13. WCAG 2.2 / motion / interaction-latency criteria (design-system + UAT basis)

- **[Fact]** WCAG 2.2 (W3C Recommendation): SC 1.4.3 Contrast
  (Minimum), AA — text "has a contrast ratio of at least 4.5:1",
  large text "at least 3:1" (direct quotes); SC 1.4.11 Non-text
  Contrast, AA — UI components/graphical objects "a contrast ratio of
  at least 3:1 against adjacent color(s)" (direct quote); SC 2.1.1
  Keyboard, A — "All functionality of the content is operable through
  a keyboard interface without requiring specific timings…" (direct
  quote); SC 2.4.7 Focus Visible, AA — "Any keyboard operable user
  interface has a mode of operation where the keyboard focus
  indicator is visible." (direct quote); SC 2.5.8 Target Size
  (Minimum), AA — "The size of the target for pointer inputs is at
  least 24 by 24 CSS pixels" with five named exceptions (spacing,
  equivalent, inline, user-agent control, essential); SC 2.2.2
  Pause, Stop, Hide, A; SC 2.3.3 Animation from Interactions, AAA —
  "Motion animation triggered by interaction can be disabled, unless
  the animation is essential…" (direct quote).
  (https://www.w3.org/TR/WCAG22/ + /WAI/WCAG22/Understanding/target-size-minimum.html
  — Accessible 2026-07-11)
- **[Fact]** `prefers-reduced-motion`: "used to detect if the user
  prefers to minimize animations and motion effects" (direct quote,
  Media Queries Level 5 WD 2026-02-19); values `no-preference` /
  `reduce`; universally implemented (MDN reference).
  (https://www.w3.org/TR/mediaqueries-5/;
  https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion
  — Accessible 2026-07-11)
- **[Fact]** INP (a stable Core Web Vital): "An INP below or at 200
  milliseconds means a page has good responsiveness." (direct quote);
  RAIL's "Complete a transition initiated by user input within
  100 ms" remains published but Google marks Core Web Vitals as "the
  recommended approach for defining performance goals over RAIL"
  (direct quote) — cite INP as primary, RAIL 100 ms as secondary.
  (https://web.dev/articles/inp; https://web.dev/articles/rail
  — Accessible 2026-07-11)
- **[Fact]** W3C WAI ARIA Authoring Practices Guide (APG) is the
  W3C-published catalog of accessible component patterns (tabs,
  dialog, menus — keyboard interaction + ARIA semantics); guidance,
  not a normative Recommendation.
  (https://www.w3.org/WAI/ARIA/apg/ — Accessible 2026-07-11)
