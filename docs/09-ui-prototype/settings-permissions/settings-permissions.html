Order confirmation policy Administrator only
Choose when the connector confirms an imported order (confirmation creates deliveries and may reserve stock). Changing this affects future orders only — already-imported quotations are never retro-confirmed.
Confirm paid orders only Recommended
Only fully paid orders auto-confirm. Reserve stock only for captured payments. Everything else imports as a quotation or waits.
Confirm paid or authorized
Also confirms authorized-not-yet-captured payments — for merchants who fulfil before capture. If an authorization later lapses, the confirmed order is flagged for review, never auto-cancelled.
Import as quotations only
Every eligible order arrives as a draft quotation; your team confirms manually in Odoo. The connector never confirms.
Manual payment gateways Administrator only
Approved manual gateways (Cash on Delivery, bank transfer, pay on pickup) get their own rule for pending payments. A manual gateway not on this list is treated like an ordinary pending payment and never auto-confirms.

Mode 1 — Odoo-controlled
Selected · Default

Odoo is the warehouse execution system. Validating an Odoo delivery creates the Shopify fulfillment with tracking. Fulfillments created outside Odoo become review cases for your team — they never touch Odoo stock automatically.

  • Zero automated inbound stock changes
  • External fulfillments: import tracking, acknowledge, or explicitly validate an exact proposal
  • Customer notifications default off
Mode 2 — Bidirectional exact reconciliation
Off · Opt-in

Everything Mode 1 does, plus: a fulfillment created in Shopify may auto-validate the matching Odoo delivery — only when it passes exact reconciliation: all 16 safety conditions (exact order, line, quantity, location, lot and duplicate checks). Any ambiguity falls back to Mode 1 behavior: a review case, no stock change.

Enabling never replays history: existing external fulfillments stay as review cases, and a read-only reconciliation scan runs first. You can switch back to Mode 1 at any time without losing anything.
Administrator only · audited
Tab (c) — Mode 2 consequences drawer · confirmation with consequences + unresolved-case list · 1366px

Enable Mode 2 for Adams Home?

Mode 2 lets an external Shopify fulfillment validate the matching Odoo delivery automatically — moving real stock — but only when every one of the 16 exact safety conditions passes. The first failed condition stops everything and creates a review case instead.

  • • Applies only to fulfillments observed after enabling — history is never replayed.
  • • A read-only reconciliation scan runs first; automation starts only after it completes cleanly.
  • • 3 unresolved external-fulfillment review cases exist today. They stay in review — they are not auto-applied.
  • • You can roll back to Mode 1 at any time; applied reconciliations, evidence and audit trail are untouched.

Connector User
4 people

Daily operations and audited resolution:

  • • View dashboard, stores, jobs, logs and settings (read-only)
  • • Retry eligible jobs · cancel non-terminal jobs · run permitted manual syncs
  • • Resolve matching and review cases (every resolution audited: who/when/what)
  • • COD reconciliation review · fulfillment review cases · tracking import
  • • Sees customer data masked by default
Cannot: change configuration or credentials, connect/disconnect stores, destructive overrides, manage access.
Connector Administrator
1 person

Everything a Connector User can, plus:

  • • Store lifecycle: connect / reconnect / disconnect · credentials & scopes
  • • All configuration: capabilities, schedules, mappings, policies, fulfillment mode
  • • Retention & privacy controls · PII visibility policy
  • • Destructive / exceptional overrides · user access assignment
An Administrator automatically has every User capability — assign exactly one role per person.
